# Independent review

Reviewed 2026-10-12: branch `code-fixes`, commit `d9c7372`. This review includes code originally written by Codex. Only this review file was created; no results were regenerated, no L2S11 scoring workflow was run, and no raw files were modified or copied.

## Verdict

The checked numerical results reproduce, but the repository is not ready to be described as a fully reproducible, submission-complete project. The most consequential problems are unsafe cleanup in the reproduction runner, a reproduction gate that can falsely pass incomplete predictions, tracked raw waveform excerpts, and an unsupported claim that repeat chronology is established. The negative finding for the selected model on L2S11 is supported; universal claims about amplitude-feature transfer and its causal limitation are stronger than the evidence. The refactor preserves the observed v1 results, including weaknesses in my original screening and repeat-ordering design; passing tests do not resolve those weaknesses.

## Refactor fidelity and reproduction evidence

Compared `7d282b2` with the constant/helper migration (`d9db0e4`), extractor refactor (`42ae820`), and current code using Git diffs and syntax trees with docstrings removed. The existing model construction, fitting, metrics, timing and plotting functions retain their computational bodies. The hull algorithms, repeat ordering/variant construction, and serial/prefetch loader are unchanged. Later formatting/documentation changes are semantically neutral in the checked v1 modules; the additional model-comparison difference only discards an unused return value.

The deliberate changes are configuration-based constants, reusable/import-safe extraction, label-blind early-reference selection, persistent `require()` checks, and new output defaults/guards. Reading 254 development MAT files into memory reproduced all 27 historical checkpoints, membership, targets, both denominators, all 254 source hashes, and OLS predictions; maximum prediction difference was **0**. Both references remain cycle 1: `L1S11_1_1_1.mat` and `L1S12_1_1_8.mat`. Independently rebuilding v2 development features in memory reproduced all 35 eligible checkpoints, including unlabelled ones, with maximum saved-feature difference **0**; the labelled non-reference counts remain 13 and 12.

`verify_reproduction.py:96` compares deterministic CSV/text contents, requires expected files, and explicitly classifies environment-dependent fields and skipped timing/plot comparisons. It should catch changes to recorded deterministic tables, but it ignores extra output files and is not a full connected raw-to-model replay: model comparison reads the recorded baseline (`scripts/model_comparison.py:638`), and coverage uses the recorded baseline and preprocessing audit. The independently regenerated baseline is compared separately, which mitigates this limitation for the present record. The stored 50-identical/4-equal-content/2-skipped report is historical evidence, not a run performed in this review; the v2 gate has the concrete weakness in R2.

Weaknesses in my original design include target-dependent reference selection in the original extractor (now corrected), accepting unique logbook dates as chronology, incomplete waveform rejection, and choosing controls that obscure the near-zero L2S11 prediction failure. A lower error than a Layup-1 training-mean control is not sufficient evidence of useful transfer.
